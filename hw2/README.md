# Расписание: MCP-сервер и эксперимент

## Файлы

- `server.py` — четыре инструмента расписания.
- `experiment.py` — часть A, часть B, LoopGuard и анализ.
- `test_project.py` — все тесты.
- `sol.ipynb` — теория, запуск эксперимента, таблицы и график с результатами.
- `data.json` — пул инструментов, разметка, поиск, настройки модели и сырые ответы всех запусков.
- `report.pdf` — отчёт на 3 страницы.
- `logs/pytest.txt` и `logs/inspector.json` — проверки тестами и MCP Inspector.

Сырые данные нужны по условию ДЗ. В `data.json` сохранены все 720 попыток части A и 60 эпизодов части B, включая неудачные. Пилот в результат не входит.

## Установка

Команды выполняются из папки `hw2`. Python 3.12:

```bash
python3.12 -m venv .venv312
source .venv312/bin/activate
python -m pip install -r requirements.txt
```

В ноутбуке выбрать Python из этого окружения. Для нового прогона нужен LM Studio, локальный сервер на `http://localhost:1234` и модель `unsloth/qwen3.5-4b`. Для просмотра и пересчёта сохранённых результатов модель не нужна.

## Сервер и проверки

```bash
python server.py
python -m pytest test_project.py -q
npx @modelcontextprotocol/inspector --protocol-era modern python server.py
```

Сервер использует stdio и MCP 2026-07-28. Inspector подключается через `server/discover`, `_meta` передаётся в запросах. Журнал сохранён в `logs/inspector.json`; в нём есть вызовы всех инструментов и ошибка с подсказкой.

| Инструмент | Что делает |
|---|---|
| schedule_get | Получает карточку занятия по ID |
| schedule_search | Ищет занятия на дату |
| schedule_teacher | Ищет занятия преподавателя |
| schedule_room | Ищет занятия в аудитории |

У параметров есть descriptions, `response_format` задан enum `concise`/`detailed`, дополнительные аргументы запрещены. В описаниях указано, когда не использовать инструмент. Ошибки возвращаются с `isError: true` и подсказкой.

Расписание фиксированное, изменяемого состояния между вызовами нет, поэтому handle не нужен. Запрет дополнительных аргументов настроен через модели SDK; версия mcp зафиксирована и схема проверяется тестом.

Размеры ответов можно проверить командой `python experiment.py sizes`. Токенизатор — `cl100k_base`, считается текст content без оболочки MCP.

| Пример | concise | detailed |
|---|---:|---:|
| get: lesson_1 | 55 | 75 |
| search: 2026-10-10 | 101 | 139 |
| teacher: А. Иванова | 162 | 222 |

## Эксперимент

Проще открыть `sol.ipynb` и выполнить ячейки. Или запускать из терминала:

```bash
python experiment.py selection
python experiment.py loops
python experiment.py analyze
```

Сохранённые попытки пропускаются, включая неудачные. Повторное выполнение ноутбука не запускает 955 запросов заново. Для нового эксперимента нужна отдельная копия `data.json`: очистить в ней массивы `selection`, `loops` и `events`, сохранив первоначальный результат.

Модель — `unsloth/qwen3.5-4b`, 4B, Q4_K_S, загруженный контекст 16493 токена. Temperature 0.3, максимум ответа 256 токенов, таймаут 60 секунд. Настройки после пилота не менялись; в ответах пилота не было текста рассуждений. Платных API и ключей нет. Подробности модели и окружения — поля `protocol` и `environment` в `data.json`.

### Часть A

100 инструментов: 4 настоящих и 96 синтетических отвлекающих, из них 24 близки к расписанию. 30 размеченных запросов: 8 get, 8 search, 7 teacher, 7 room. Для N = 5, 20, 50, 100 используются вложенные наборы с seed 42; правильные инструменты присутствуют во всех наборах. Порядок попыток перемешан с seed 123.

A получает все N описаний. B получает top-5 по эмбеддингам `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`; сходство косинусное. Поиск внешний, в обоих вариантах один запрос LLM. Токены берутся из `usage.prompt_tokens`, стоимость вычисления эмбеддингов не включена. Поиск после пилота не подгонялся. Для пересчёта поиска с нуля модель эмбеддингов нужно заранее скачать; существующий поиск уже сохранён.

30 запросов × 3 повтора × 4 N × 2 варианта = 720 попыток. Ошибки и незавершённые ответы считаются неправильными. 95%-е интервалы: 10 000 бутстрэп-выборок по запросам; три повтора одного запроса остаются вместе. При 100% наблюдаемой точности интервал вырождается, что не устраняет неопределённость за пределами выборки.

| N | A: верно / 90 | B: верно / 90 | Recall@5 | Средний вход A | Средний вход B |
|---|---:|---:|---:|---:|---:|
| 5 | 90 | 90 | 100.0% | 173.2 | 173.2 |
| 20 | 85 | 63 | 73.3% | 509.2 | 178.5 |
| 50 | 90 | 57 | 63.3% | 1125.2 | 178.6 |
| 100 | 89 | 42 | 46.7% | 2267.2 | 185.7 |

### Часть B

20 задач в трёх условиях: пустой ответ (`empty`), пустой ответ с LoopGuard (`guard`), подсказка вместо пустоты без guard (`hint`). Всего 60 эпизодов, до 10 шагов на каждый. Успех требует ID с разрешённой даты, найденный поиском и полученный через get.

Поиск с вероятностью 0.5 возвращает пустой content без объяснения. В `hint` вместо пустоты возвращается `isError: true` с подсказкой попробовать другой date. Вероятность — параметр генератора, фактическая доля пустых ответов может отличаться от 50%.

Seed нестабильности 300–319 попарно одинаков во всех условиях; порядок эпизодов перемешан с seed 456. Генерация LLM не фиксируется seed. LoopGuard — код лекции, `max_same=3`, `window=6`; сигнал добавляется к наблюдению модели. «3 повтора» трактуется как порог guard, а не дополнительные прогоны. Метрика петли отдельно проверяет три одинаковых вызова подряд или A-B-A-B.

| Условие | Петли / 20 | Успех / 20 | Средние шаги | Средний вход | Средние все токены |
|---|---:|---:|---:|---:|---:|
| empty | 0 | 15 | 3.85 | 1636.8 | 1723.5 |
| guard | 0 | 16 | 3.55 | 1424.2 | 1502.1 |
| hint | 0 | 16 | 4.35 | 2074.4 | 2175.8 |

Петель не обнаружено; guard ни разу не сработал. По этим данным нельзя определить, что лучше предотвращает петли. Неудачные эпизоды не исключены. Всего было 955 запросов модели: 720 в A и 235 в B. Бюджет внешних API — 0 долларов.

Три ограничения: синтетические данные одного домена; одна квантованная модель и один поиск; маленькая выборка с искусственными сбоями и бюджетом 10 шагов.
